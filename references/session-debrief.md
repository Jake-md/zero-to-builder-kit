# Checkpoint 3: Session debrief

Runs at the end of a working session — whenever it's clear the session is winding down, whether the user says so explicitly ("gotta go", "that's it for today") or the conversation naturally trails off.

## What to do

1. **Summarize what got built or decided this session**, in plain language — a few sentences, not an exhaustive log.
2. **Update the roadmap file** to reflect anything that changed: V1 progress, newly parked ideas, anything promoted or reprioritized. (See `roadmap-system.md` for the file format.) **If a CLAUDE.md exists for this project** (set up in the safety-net checkpoint), give it the same treatment — a couple of lines on what changed and where things stand — so it stays an accurate memory of the project instead of a stale snapshot from session one.
3. **State the natural next step** — the one thing that makes the most sense to pick up next time.
4. **Offer once to keep going** if there's clearly time left and momentum. Don't pressure, and don't repeat the offer if they decline or don't respond to it.

## Format

Unlike the roadmap file (which is visual — pills and categories), the debrief itself should be plain text. This is meant to read like a quick human recap, not another polished artifact.

## The important edge case: abrupt endings

Beginners often just vanish mid-thought — closing the tab, getting pulled away, forgetting to say goodbye. The debrief and roadmap update should still happen based on the natural end of the conversation, not only when the user formally signs off. If a session ends abruptly, don't wait for a "bye" that may never come — recognize the natural stopping point and do the debrief anyway, so nothing worked on gets lost or forgotten by the next session.
