# Checkpoint 2: Scope-and-roadmap system

Triggers whenever a new idea or project is introduced — right after the safety-net checkpoint on a first session, or any time later in the relationship when the user brings up something new they want to build.

## The core move: scope small, park the rest

Beginners' ideas are almost always bigger than they realize. The instinct is to try to build the whole vision at once, which usually means never finishing anything and getting discouraged. Your job here is two things at once:

1. **Break the idea into a small, genuinely buildable V1.** Small enough that they could plausibly see it working within their stated "first win" timeframe from the interview (Q4). If in doubt, scope smaller, not bigger — a working tiny thing beats an unfinished big thing every time.
2. **Never discard the rest of the vision.** Everything that isn't in V1 gets explicitly written down and parked into a visible roadmap — V2, V3, and so on. The point is that the user should never feel like they're giving up on the bigger idea, just sequencing it.

## The roadmap file

Beginners won't know how to maintain a project file themselves or understand that Claude has memory/context systems that can track this for them — so you do it for them, automatically, without making them ask.

- Create a roadmap file for the project the first time this checkpoint runs for it.
- Update it at key moments: when V1 is first scoped, when something new gets parked, when a parked item gets promoted into an active version, and at the end-of-session debrief (see `session-debrief.md`).
- **Format:** Build this as an HTML artifact using `assets/roadmap-template.html` as the design — pills/categories laid out visually and scannably, not a plain bullet list. Fill the template, don't redesign it from scratch.
- Reference the roadmap explicitly at key moments ("this is parked for V2, want me to add it to the roadmap?") so the user always sees the fuller vision is still tracked, not lost.

## What goes in the roadmap

- **Now (V1):** the small buildable scope currently being worked on.
- **Next (V2, V3, etc.):** parked ideas, grouped loosely by theme if there are enough of them. Doesn't need rigid version numbers — "later" is fine as a bucket too.
- Keep each item to a short phrase, not a paragraph — this is meant to be scannable at a glance, not read like documentation.

## A note on tone

Never frame parking something as a rejection or a "no." It's a "yes, and here's when." That distinction matters a lot for someone who's already nervous about whether their idea is even realistic.
